# Knowledge Card System

## 1. 目标

Knowledge Card System 是「再玩」的通用学习模块。用户可以把任何学科的知识点保存为卡片，通过回忆、选择、录音、跟读或听力练习完成复习。

卡片系统自身负责知识内容、练习和复习记录。是否因此完成今日任务，由 Task System 根据学习任务的目标进行判断。

## 2. 产品原则

- 卡片不绑定具体学科，英语、编程、考试、读书和工作知识使用同一套基础模型。
- 内容与练习方式分离。同一个知识点可以使用不同卡片类型训练。
- 自动判定必须可解释，结果需要展示识别内容、正确答案或失败原因。
- “语音能够被识别”不等于“发音标准”，未接入专业评测前不得展示为发音分数。
- 权限拒绝、录音中断或识别失败不得自动判定通过。

## 3. 核心对象

### 3.1 KnowledgeDeck

知识库用于组织同一主题的卡片，例如“Flutter”“英语四级”或“计算机网络”。

### 3.2 KnowledgeCard

卡片保存知识内容和练习配置。所有类型共享题面、参考答案、解析、标签和来源；不同类型使用各自的扩展字段。

### 3.3 ReviewRecord

复习记录保存一次作答的结果、耗时和尝试次数，用于统计、安排下次复习以及判断学习任务进度。

## 4. 卡片类型

### 4.1 问答卡

用户先看问题并主动回忆，然后翻面查看答案，手动选择“不会”“模糊”“掌握”。

### 4.2 单选题

用户选择一个选项后提交。正确选项以稳定标识保存，不依赖选项位置。

### 4.3 多选题

用户可以选择多个选项。只有所选答案集合与正确答案集合完全一致时才通过。

### 4.4 录音回答卡

用户录制口头回答并可回放。第一阶段支持用户手动判定；后续可以将语音转写结果与参考答案或关键词比较。

### 4.5 单词跟读卡

用户听标准读音并跟读。第一阶段仅判断是否检测到有效语音且转写结果包含目标文本。专业发音评测作为后续能力。

### 4.6 听力卡

系统播放单词或句子，用户通过输入、选择或录音回答。音频可以来自用户录音、导入文件或文字转语音。

## 5. 判定规则

| 类型 | 第一阶段判定 | 后续能力 |
|---|---|---|
| 问答卡 | 用户自评 | 根据历史调整复习间隔 |
| 单选题 | 所选选项等于正确选项 | 选项随机排序 |
| 多选题 | 所选集合完全等于正确集合 | 部分正确反馈 |
| 录音回答 | 用户自评 | 转写与关键词匹配、语义判定 |
| 单词跟读 | 有效语音且识别到目标文本 | 音素、重音和流利度评测 |
| 听力卡 | 按回答方式判定 | 播放次数及难度控制 |

语音相关卡片需要区分以下结果：权限不可用、没有检测到声音、识别失败、答案不匹配、通过。只有最后一种可以计入任务进度。

## 6. 复习计划

第一版采用可解释的简单间隔：

| 结果 | 下次复习 |
|---|---|
| 不会或答错 | 次日 |
| 模糊或困难 | 2 天后 |
| 掌握或答对 | 4 天后 |
| 非常熟练 | 7 天后 |

数据模型保留调度字段，后续可以替换为间隔重复算法，而不改变页面和任务接口。

## 7. 与任务系统的关系

学习任务引用一个知识库及目标条件，例如：

- 复习 10 张卡片。
- 正确完成 8 张选择题。
- 通过 5 张单词跟读卡。

ReviewRecord 是学习进度的事实来源。Task System 汇总当天符合条件的复习记录，并决定学习任务是否完成。Knowledge Card System 不直接改变 `Locked` 或 `Unlocked`。

## 8. 技术边界

Flutter 负责卡片内容、作答流程、答案判定、复习调度、任务进度和本地数据。

iOS 与 Android 原生层只提供必须依赖平台的能力，包括麦克风权限、录音、音频播放、语音识别和文字转语音。平台错误通过统一接口映射到 Dart 层。

专业发音评测若需要第三方服务，应位于可替换的数据服务层，不得写进卡片实体或页面逻辑。

## 9. 实施阶段

### 阶段 A：通用卡片基础

- 将现有 Flashcard 模型演进为 KnowledgeCard。
- 完成知识库及问答卡的创建、编辑、删除和本地持久化。
- 保留已有翻卡交互。

### 阶段 B：选择题

- 完成单选、多选、自动判题、答案解析和重试。
- 保存 ReviewRecord。

### 阶段 C：复习系统

- 完成今日待复习列表、进度、结果选择和简单复习间隔。

### 阶段 D：录音回答

- 完成权限处理、录制、停止、回放、删除和手动判定。
- 再增加语音转写及关键词匹配。

### 阶段 E：跟读与听力

- 完成标准读音播放、目标文本识别和听力作答。
- 评估是否接入专业发音评测服务。

### 阶段 F：任务闭环

- 增加学习任务及进度汇总。
- 学习任务完成后触发统一解锁规则重算。
- 验证跨天、重试、重复提交和离线状态。

## 10. 验收重点

- 不同学科可以使用同一套知识库和卡片模型。
- 卡片增删改后重启应用数据仍然存在。
- 单选和多选判定不依赖选项顺序。
- 同一次作答不会重复累计任务进度。
- 权限拒绝、录音中断和识别失败不会误判通过。
- 学习任务只通过 Task System 影响解锁状态。
